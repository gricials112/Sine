# Sine — 设计方案 (Design Proposal)

> 文档版本：v1.0 · 状态：草案 → 已纳入评审 · 平台：iOS 16.0+ · 阶段：阶段一（设计方案）

---

## 1. 产品定位与目标

### 1.1 一句话定位
**一款 100% 本地离线、零服务器开销的 4 音轨 (人声 / 鼓 / 贝斯 / 其他) 分离与实时混音 App，主打"扒谱神器"场景，使用现代拟真 (Modern Skeuomorphic) 工业美学界面。**

### 1.2 目标用户
| 用户画像 | 核心诉求 | 关键功能映射 |
|---|---|---|
| 翻唱/二创 UP 主 | 去除人声做伴奏、提取干声 | 音轨分离 + 自定义导出 |
| 乐器学习者 (吉他/贝斯/鼓) | 单独听某一轨、降速扒谱、移调到顺手 Key | Solo/Mute + 变速变调 |
| 音乐爱好者 / DJ | 即时混音、做 Mashup | 迷你调音台 + 混音导出 |
| 隐私敏感用户 | 不愿把音乐上传云端 | 全本地 NPU 推理 |

### 1.3 差异化卖点 (与竞品 Moises / LALAL.AI 对比)
1. **完全离线**：无需联网、无订阅次数限制、无文件上传等待，隐私零泄露。
2. **零服务器成本**：推理跑在 Apple Neural Engine (ANE)，开发者无云算力账单。
3. **工业拟真触感**：CoreHaptics 阻尼反馈 + Metal 120Hz FFT 波形，体验对标硬件设备。

### 1.4 非目标 (Out of Scope, v1.0)
- 不做 6 轨 / 8 轨分离 (吉他、钢琴独立轨) —— 用 EQ 补偿替代 (见难点三)。
- 不做云端协作、社区分享。
- 不做 MIDI 扒谱 / 自动和弦识别 (列入 v2.0 储备)。
- 不做 Android (架构强依赖 ANE + AVAudioEngine)。

## 2. 系统总体架构

### 2.1 分层架构
```
┌─────────────────────────────────────────────────────────────┐
│  Presentation 层 (SwiftUI + Metal + CoreHaptics)             │
│  · 导入页 · 处理进度页 · 调音台主页 · 导出页                  │
│  · MetalFFTView (波形)  · FaderView/KnobView (拟真控件)      │
├─────────────────────────────────────────────────────────────┤
│  Application / ViewModel 层 (Combine, @MainActor)            │
│  · ImportViewModel · SeparationViewModel · MixerViewModel    │
│  · ExportViewModel                                            │
├─────────────────────────────────────────────────────────────┤
│  Domain / Service 层 (纯 Swift, 可单元测试)                  │
│  ┌───────────────┐ ┌────────────────┐ ┌──────────────────┐  │
│  │ AudioImport   │ │ SeparationEngine│ │ PlaybackEngine   │  │
│  │ Service       │ │ (CoreML+Chunk)  │ │ (AVAudioEngine)  │  │
│  └───────────────┘ └────────────────┘ └──────────────────┘  │
│  ┌───────────────┐ ┌────────────────┐ ┌──────────────────┐  │
│  │ ExportService │ │ DSP/OverlapAdd │ │ HapticsService   │  │
│  └───────────────┘ └────────────────┘ └──────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│  Platform / Framework 层                                     │
│  AVFoundation · CoreML · Accelerate(vDSP) · Metal · CoreHaptics│
└─────────────────────────────────────────────────────────────┘
```

### 2.2 端到端数据流 (Pipeline)
```
[本地视频/音频]
   │  ① AVAssetReader 解码
   ▼
[PCM Float32, 44.1kHz, 立体声]  ── 写入临时 WAV (可选缓存)
   │  ② Accelerate 切块 (15~30s/块, 含 overlap)
   ▼
[Chunk_0, Chunk_1, ... Chunk_n]
   │  ③ 逐块送入 CoreML (HT-Demucs FP16, ANE)
   │     每块 autoreleasepool 包裹，推理后显式释放
   ▼
[每块 4 轨输出: vocal/drums/bass/other]
   │  ④ Overlap-Add 重叠相加无缝拼接
   ▼
[4 条完整 PCM 轨] ── 落盘为 4 个 CAF/WAV (stem 文件)
   │  ⑤ 挂载到 AVAudioEngine: 4×PlayerNode → (EQ on Other) → 4×TimePitch → MixerNode → Output
   ▼
[实时混音播放 / Solo / Mute / 变调变速]
   │  ⑥ 离线渲染 (AVAudioEngine manualRenderingMode) 按用户勾选轨道与参数合成
   ▼
[导出 m4a/wav 到相册/文件]
```

### 2.3 关键技术选型
| 领域 | 选型 | 理由 |
|---|---|---|
| 解码取流 | `AVAssetReader` + `AVAssetReaderTrackOutput` | 原生、快、支持几乎所有容器 |
| 分离模型 | HT-Demucs v4 四音轨量化版 (主) / Spleeter-CoreML (轻量降级) | 质量优先，低端机降级 |
| 模型格式 | `.mlmodelc`，FP16 (低端) / INT8 (实验) | ANE 加速 + 内存可控 |
| 切块/重叠相加 | `Accelerate` (vDSP) | 高性能向量运算 |
| 播放引擎 | 单例 `AVAudioEngine` + 4×`AVAudioPlayerNode` | 统一时钟，避免漂移 |
| 变调变速 | `AVAudioUnitTimePitch` (每轨一个) | 保真度高，原生 |
| Other 轨补偿 | `AVAudioUnitEQ` (10 段参量) | 弥补轻量模型频段重叠杂音 |
| 波形渲染 | `Metal` + `MTKView` (120Hz) | 高帧率，GPU 绘制不掉帧 |
| 触感 | `CoreHaptics` (`CHHapticEngine`) | 阻尼/段落齿轮感 |
| 导出 | `AVAudioEngine` 离线渲染 + `AVAudioFile` | 与播放链路一致，所见即所得 |

## 3. 核心模块设计

### 3.1 AudioImportService (导入与取流)
- **职责**：从相册 (`PHPicker`)、文件 (`UIDocumentPicker`)、微信分享 (`UIActivity` / `Document Interaction`) 接收视频/音频；用 `AVAssetReader` 抽取音频；统一重采样为 44.1kHz / Float32 / 立体声。
- **关键设计**：
  - 解码后立即落临时 WAV，避免分离阶段把整首歌占在内存里。
  - 时长上限策略：>10 分钟提示用户裁剪 (内存 + 推理时长保护)。
  - 校验：无音轨视频 → 友好报错。

### 3.2 SeparationEngine (分离引擎 — 核心难点 1)
- **职责**：把整首歌的 PCM 切块 → 逐块 CoreML 推理 → Overlap-Add 拼接 → 输出 4 个 stem 文件。
- **抗 OOM 设计 (难点一)**：
  - **Chunking**：默认 chunk = 已用 `segment * sampleRate` 计算的样本数 (默认 segment=20s)，相邻块 overlap = 2s (可调)。
  - **autoreleasepool**：每个 chunk 推理循环体包裹 `autoreleasepool { ... }`，推理结束后 `MLModel` 输出 `MLMultiArray` 立即转 Swift `[Float]` 并置 nil。
  - **降级链**：检测 `ProcessInfo.physicalMemory`：≤4GB → 强制 Spleeter-CoreML + chunk=15s；≤6GB → HT-Demucs FP16 + chunk=20s；>6GB → chunk=30s。
  - **进度回调**：`Progress` (0~1) 上报，可取消 (`CancellationToken`)。
- **Overlap-Add (无缝拼接)**：用三角/Hann 窗对重叠区交叉淡入淡出，避免块边界爆音。算法在 Python reference 中已验证 (见 `reference/`)。

### 3.3 PlaybackEngine (实时混音 — 核心难点 2)
- **职责**：4 轨同步播放、Solo/Mute、实时音量、实时变调变速。
- **抗漂移设计 (难点二)**：
  - **单例 AVAudioEngine**：唯一主音频图。
  - **节点图**：`4×PlayerNode → 4×TimePitch → MixerNode → MainMixer → Output`；Other 轨在 TimePitch 前插入 `AVAudioUnitEQ`。
  - **采样点对齐**：播放/拖动滑块/seek 时，取统一 `AVAudioTime`（基于 `lastRenderTime` + 固定 startDelay），4 轨用同一 `AVAudioTime` 调 `scheduleSegment`，保证采样级对齐。
  - **Solo/Mute**：通过各轨 `MixerNode` 输入 `volume`/`outputVolume`，不停止 PlayerNode (避免重新调度引入漂移)。

### 3.4 DSP / EQ (Other 轨补偿 — 核心难点 3)
- Other 轨链路：`PlayerNode → AVAudioUnitEQ(10 band) → TimePitch → Mixer`。
- 预设：`吉他增强` / `钢琴增强` / `中频削弱` / `自定义`，每个预设是一组 10 段 (freq, gain, Q, filterType) 参数。
- 让用户用成熟 DSP 弥补轻量模型的金属杂音，而非死磕模型。

### 3.5 ExportService (高精度自定义导出)
- 复用 PlaybackEngine 的节点图，切到 `manualRenderingMode = .offline`。
- 用户勾选要输出的轨道 (任意组合) + 是否套用当前音量/速度/Key/EQ。
- 输出格式：`m4a (AAC)` 默认 / `wav (无损)` 可选；写相册或"文件"。

### 3.6 HapticsService (触感)
- `CHHapticEngine` 常驻；推子/旋钮拖动跨过刻度时触发短促 transient (齿轮段落感)，强度随速度变化。
- 失败优雅降级 (老设备无 Taptic / 引擎被系统回收时自动重启)。

### 3.7 MetalFFTView (动态波形)
- `MTKView` 60/120Hz；从播放 tap 取 PCM → vDSP_FFT → 频谱 → 顶点缓冲；线条粗细/辉光/流速随推子音量与频谱能量演变。
- 与音频线程解耦：音频 tap 写环形缓冲，渲染线程读，避免阻塞音频。

## 4. 工程与质量

### 4.1 目录结构 (规划)
```
Sine/
  App/                 # 入口、AppState
  Features/
    Import/  Separation/  Mixer/  Export/
  Core/
    Audio/   (PlaybackEngine, AudioGraph)
    Separation/ (SeparationEngine, Chunker, OverlapAdd)
    DSP/     (EQPresets)
    Haptics/ MetalFFT/
    Models/  (Stem, Project, TrackState)
  Resources/ (.mlmodelc, EQ 预设 json)
  Tests/     (XCTest)
reference/   # Python 算法参考实现 + 可运行测试
docs/        # 设计/需求/交互文档
```

### 4.2 测试策略
| 层 | 手段 | 本环境可运行? |
|---|---|---|
| 核心 DSP 算法 (Overlap-Add / 采样对齐 / EQ) | **Python 参考实现 + pytest** | ✅ 可运行 (本环境验证) |
| Swift 纯逻辑 (Chunker 边界、降级策略、参数映射) | XCTest 单元测试 | ⚠️ 需 macOS/Xcode |
| 音频图 / CoreML / Metal / Haptics | 真机集成测试 + 手动用例 | ❌ 需真机 |

> 由于本 CI 环境为 Linux 无 Xcode 工具链，阶段六"功能测试"以 **Python 参考实现验证核心算法** + **完整 XCTest 与手动测试用例清单** 交付；真机编译运行需在 macOS 上完成。

### 4.3 风险登记 (摘要，详见 FRD 评审)
| 风险 | 等级 | 缓解 |
|---|---|---|
| 大模型 OOM 被 Jetsam 杀 | P0 | Chunking + autoreleasepool + 内存降级链 |
| 多轨变速失同步 | P0 | 单 Engine + 统一 AVAudioTime 采样对齐 |
| Other 轨金属杂音 | P1 | 10 段 EQ 补偿预设 |
| ANE 不可用回落 CPU 太慢 | P1 | computeUnits 探测 + 进度可取消 |
| 模型体积导致 App 过大 | P1 | 按需下载/捆绑取舍 (评审决议) |
